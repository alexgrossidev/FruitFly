## Deviations from the starting-point architecture (read these first)

Two changes were needed before anything learned at all; both are numerical/architectural choices, neither touches the locked task definition or the connectome topology, and all Milestone 2 conditions use the same settings. Both are configurable (`ModelConfig` in `src/model.py`, `--init-row-sum` / `--settle-steps` on `src/train.py`).

1. **Initial weight gain (`init_row_sum=1.0`).** `initializer="normalized_synapse_count"` gives each edge `log1p(synapse_count) / sqrt(in_degree)`. On the bundled 100-neuron sample (mean in-degree 36, all weights positive) that sums to a max absolute row sum of **36.4**, so `tanh` saturates on the first recurrent step and the encoder's sub-unit input drive is invisible. Every run at the raw scale stayed at the class prior (balanced accuracy 0.50–0.55, loss ≈ 0.645 = entropy of a 65/35 label) for every learning rate, leak and bias setting tried — see `results/sweep_milestone1.txt`. Multiplying the *starting* weights by one scalar so the max row sum is 1.0 (an echo-state-style unit gain; the weights remain free parameters) fixed it at every gain tried between 0.5 and 4.0. The same rescale is applied to each control graph, so the conditions stay matched.
2. **Two silent settle steps after the tenth digit (`settle_steps=2`).** Input and output neurons are disjoint slices, so a digit presented at step *t* can first affect an output neuron at step *t+1*. With `readout="last"` and exactly 10 steps, the tenth digit can never reach the decoder, which caps accuracy at ~96.1% (`1 - 0.1 * 0.9**9` of lists have their only 6, or only 7, in the last slot). Seventeen otherwise different sweep configurations stopped at the identical 96.53% / 95.61% — the signature of that cap. Appending two zero-drive recurrent steps (the digits are still presented one per step, in order, exactly once; the core just runs 12 steps instead of 10) removes it: Milestone 1 goes from 95.5% to 100%. The replay files therefore have 12 frames, not 10.

Also changed: learning rate `1e-2` instead of the README's suggested `2e-3` (both work after fix 1; `1e-2` reaches 95% validation balanced accuracy in 1–4 epochs where `2e-3` needs 8+). Everything else is as in the README: 16 input / 16 output neurons chosen as the first/last 16 body ids, `tanh`, `leak=0.4`, no bias, Adam, `BCEWithLogitsLoss`, one-hot digits fed as a `[batch, 10, 16]` sequence in a single call.

Produced by `python -m src.export_replay` from `results/checkpoints/real_seed0.pt` (the Milestone 2 real-connectome seed-0 run).   - What is exported: the trained core run directly (not through the decoder) via a second `ConnectomeRNN` that reads out **all 100 neurons** and carries the trained weights (asserted equal on the 16 readout neurons to the trained core's own output). 12 frames, one per recurrent step, 1 s apart: frames 0–9 = state after digit *t* is presented, frames 10–11 = the two silent settle steps. Every neuron is listed in every frame (the viewer zeroes omitted ids).
  - Normalization used (must match what's declared in the JSON's `source.normalization`): **`|h_t|`, the absolute value of each neuron's leaky-tanh state**, which is in [−1, 1] by construction, so this is a fixed rescale to [0, 1] with no per-run min-max; sign is discarded; 0 = rest. Declared verbatim in every file.
  - Id bridge: all 100 sample body ids are in the viewer's visible selection (`groups.bin < 3`; all are group 1, "central") — checked in `tests/test_replay.py`.
  - Validation, three ways: (1) `src.export_replay.validate_replay`, a Python mirror of `viewer/src/lib/replay.ts`; (2) `node scripts/validate_replay.mjs results/replays/*.json`, which imports the viewer's own `parseReplay` and atlas — 4/4 valid; (3) `node scripts/viewer_load_test.mjs results/replays/*.json` drives the *running* Vite dev server in headless Chrome, uploads each file through the real "Load model JSON" file input, and checks that no `role="alert"` error appears and the provenance panel switches to "PREDICTED OUTPUT" — 4/4 accepted.
